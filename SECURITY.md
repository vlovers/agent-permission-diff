# Security policy

RuleWitness 0.2.x (formerly AgentPermissionDiff) is an experimental static analyzer. It is not a sandbox, enforcement mechanism, or complete model of Claude Code runtime permissions. See README for the supported scope and unknowns. A modeled ALLOW, a passing assertion suite, or a scoped CI gate does not guarantee runtime execution or full security.

The analyzer must not execute analyzed configuration, fetch revisions, read machine credentials, send configuration over the network, or modify Git state. Fixed Git subprocesses and bounded JSON/glob processing are the principal input boundaries. Reports contain original supported permission strings and should be treated as potentially sensitive. Unsupported values are represented by fingerprints, not redacted copies with a confidentiality guarantee; fingerprints can be guessed for low-entropy values.

Run analysis in an isolated environment when repository metadata or Git itself is untrusted. Resource limits reduce, but do not eliminate, denial-of-service risk. An empty finding list or exit code 0 does not prove a repository safe. `complete` remains false for this MVP.

The [v0.1 audit](docs/audit-v0.1.md) records corrected false-negative cases and remaining limits. The library's `evaluate()` returns raw configured rule-layer decisions; it must never be used to authorize execution. Unsupported Git no-lazy-fetch behavior, malformed UTF-8 and analysis-limit failures produce an error rather than a partial success report. JSON v1 is a report format, not a validated policy import format.

For a vulnerability, use [Report a vulnerability](https://github.com/vlovers/agent-permission-diff/security/advisories/new) once the maintainer has enabled private reporting. If the form is unavailable, open only a minimal [issue requesting a private contact](https://github.com/vlovers/agent-permission-diff/issues), without exploits, secrets, or sensitive configuration. Do not disclose the vulnerability in a public issue or pull request. No email security contact or response-time commitment has been established. Private vulnerability reporting was verified enabled via the read-only GitHub API on 2026-10-17. A responsible maintainer and security-notification owner must still be confirmed before npm publication.

Maintainers: in the public repository's **Settings → Security and quality → Advanced Security**, enable **Private vulnerability reporting**. Confirm that **Security → Advisories** shows **Report a vulnerability**, and subscribe to security-alert notifications so reports reach a responsible maintainer. This is a repository setting; committing this file does not enable it. Follow [GitHub's official instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository). Record successful enablement in the [release checklist](docs/release-readiness.md) before inviting reports.

Only the latest reviewed 0.2.x revision is intended to receive fixes during the experimental phase; v0.1 audits remain historical records. No response-time guarantee is offered. See [current release preparation](docs/release-v0.2.0.md).
